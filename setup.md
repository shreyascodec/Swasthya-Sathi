# Swasthya Sathi — Installer & Setup Guide

Detailed reference for the Windows appliance installer: what each file does, how first-run works, how to build a release zip, and how to troubleshoot.

For a one-page clinic handout, see `START_HERE.txt`.  
For general kiosk deploy (env vars, warmup, Linux), see `DEPLOY.md`.

---

## 1. Who uses what

| Audience | What they do |
|----------|----------------|
| **Clinic / non-tech user** | Run `SwasthyaSathiSetup.exe` once (Next → Install → Finish), then the **Swasthya Sathi** desktop icon daily |
| **Build / IT person** | Run `deploy\build_release.ps1` → hand over the single `dist\SwasthyaSathiSetup.exe` |
| **Developer** | Use `deploy\appliance_setup.py` CLI flags; `start_kiosk.bat` for local runs |

**Design rules**

- A normal Windows install wizard (Next → Install → Finish), then one automatic first-run  
- Clinic PC needs **nothing** pre-installed — the installer bundles Python (and Ollama)  
- No admin / no UAC — per-user install into a writable folder  
- Auto-detect CUDA GPU → GPU path; otherwise CPU  
- Internet allowed on **first run** (models download); offline-capable afterward  
- Clinic PC does **not** need Node.js  

> **Note:** The Inno Setup installer (`SwasthyaSathiSetup.exe`) is the current, recommended path. The older thin `Setup.exe` (PyInstaller launcher, `deploy\build_setup_exe.ps1`) still works but requires Python already on the target PC — the Inno installer removes that requirement.

## 2. File map (installer-related)

### User-facing (repo root)

| File | Purpose |
|------|---------|
| **`Setup.exe`** | Primary first-run launcher (thin PyInstaller wrapper). Opens progress UI, runs setup, then starts the app. |
| **`setup.bat`** | Fallback if `Setup.exe` is missing; launches `Setup.exe` or runs `appliance_setup.py --gui --start`. |
| **`SwasthyaSathi.bat`** | Daily start. If setup incomplete → runs GUI setup; else `--start-only`. Auto-repair with `--force` if start fails. |
| **`start_kiosk.bat`** | Same appliance start path (legacy name). Prefer `SwasthyaSathi.bat` for clinics. |
| **`START_HERE.txt`** | Plain-language instructions for end users and zip builders. |

### Build / engine (`deploy\`)

| File | Purpose |
|------|---------|
| **`installer.iss`** | Inno Setup script for **`SwasthyaSathiSetup.exe`**. Copies the app tree to a per-user writable folder, silently installs bundled Python if none, creates desktop/Start-Menu shortcuts + uninstaller, then launches first-run setup. |
| **`build_release.ps1`** | Full release: `npm` build → `frontend\dist`, download bundled Python + Ollama into `deploy\bundle\`, then compile `installer.iss` → `dist\SwasthyaSathiSetup.exe`. |
| **`bundle\`** | Downloaded offline installer (`python-installer.exe`). Git-ignored; fetched by `build_release.ps1`. Ollama is not bundled by default — drop `OllamaSetup.exe` here (and re-add its `Source` line in `installer.iss`) to ship it offline. |
| **`appliance_setup.py`** | Full bootstrap: detect device, venv, pip, Ollama/Phi, UI check, STT/TTS weights, `local.yaml`, warm RapidOCR, start kiosk. |
| **`setup_launcher.py`** | *(Legacy)* Source for the thin `Setup.exe`. Finds `.venv` or host Python ≥3.10, then runs `appliance_setup.py --gui --start`. Requires Python already on the target. |
| **`build_setup_exe.ps1`** | *(Legacy)* Builds thin `Setup.exe` via PyInstaller from `setup_launcher.py`. |
| **`Setup.spec`** | Generated by PyInstaller (safe to regenerate). |
| **`install_windows_startup.ps1`** | Optional: scheduled task to launch kiosk at Windows logon. |
| **`swasthya-sathi.service`** | Linux/Orin systemd unit (not used by Windows Setup.exe). |

### State & config produced by setup

| Path | Purpose |
|------|---------|
| **`runtime\setup_state.json`** | Marker that setup completed (`ok`, GPU info, timestamp). |
| **`config\env\local.yaml`** | Auto-written hardware profile (`device: cuda|cpu`, VRAM ceiling, etc.). Selected via `SS_ENV=local`. |
| **`logs\setup.log`** | Setup transcript for support. |
| **`.venv\`** | Python environment created/used by setup. **Do not delete** after install. |
| **`models\weights\`** | Downloaded STT/TTS assets (Vaani, multilingual Whisper, Piper). |
| **`frontend\dist\`** | Prebuilt SPA (must exist before clinic first-run; built on the build PC). |

## 3. End-user flow

### First time

1. Double-click **`SwasthyaSathiSetup.exe`** (a single file — nothing else to copy).  
   If Windows shows *"Windows protected your PC"*, click **More info → Run anyway** (unsigned, see §11).
2. Wizard: **Next → Install → Finish** (per-user, no admin prompt).  
   - If the PC has no Python 3.10+, the wizard silently installs the bundled Python first.
3. On Finish the app launches and a progress window runs automatically (no choices):
   - Detect GPU / CPU  
   - Create `.venv` and install packages  
   - Ensure Ollama (winget / direct download; internet is available at install) + pull `phi3.5:3.8b`  
   - Download Vaani Hindi STT, multilingual Whisper, Piper English voice  
   - Write `config\env\local.yaml`  
   - Warm RapidOCR / touch Phi  
   - Start server and open Chrome (`http://127.0.0.1:8000`)
4. Wait until the UI shows ready (warmup chip clears).

**Expect:** 10–30+ minutes on first run depending on network (speech models are large).

### Every day after

Double-click the **Swasthya Sathi** desktop icon (runs `SwasthyaSathi.bat`).

- If `runtime\setup_state.json` is valid and verify passes → start only.  
- If setup never finished → GUI setup again.  
- If start fails → repair setup (`--force`) then start.

### If something fails

1. Confirm internet (first run / repair).  
2. Run **`Setup.exe`** again (idempotent; skips finished steps).  
3. Read **`logs\setup.log`**.  
4. Confirm Python 3.10+ and Ollama can install/start on that machine.

## 4. Build-PC flow (make the zip)

**Requirements on the build machine only**

- Node.js LTS + npm (for `frontend\dist`)  
- **Inno Setup 6** (provides `ISCC.exe`) — <https://jrsoftware.org/isdl.php>  
- Internet (first run downloads the bundled Python + Ollama installers)

```powershell
cd C:\Projects\Swasthya-Sathi
powershell -ExecutionPolicy Bypass -File deploy\build_release.ps1
```

This script:

1. Refreshes PATH and resolves `npm.cmd` (including `C:\Program Files\nodejs\`).  
2. Runs `npm ci` / `npm install` + `npm run build` → `frontend\dist`.  
3. Downloads the bundled **Python** (pinned, e.g. 3.12.7) and **Ollama** installers into `deploy\bundle\` (cached; skipped if already present).  
4. Compiles `deploy\installer.iss` with `ISCC.exe` → **`dist\SwasthyaSathiSetup.exe`**.

Hand the clinic that **single file** — `dist\SwasthyaSathiSetup.exe`. It carries the whole app tree, the prebuilt UI, and the bundled Python/Ollama installers. Nothing else to copy.

### Legacy: rebuild the thin `Setup.exe` only (requires Python on the target)

```powershell
cd C:\Projects\Swasthya-Sathi
powershell -ExecutionPolicy Bypass -File deploy\build_setup_exe.ps1
```

### Optional: start at Windows logon

```powershell
powershell -ExecutionPolicy Bypass -File deploy\install_windows_startup.ps1
```

Registers scheduled task `SwasthyaSathiKiosk` → `start_kiosk.bat` at logon.

## 5. What `appliance_setup.py` does (step by step)

| Step | Action | Failure behavior |
|------|--------|------------------|
| Detect | `nvidia-smi` → CUDA name + VRAM; else CPU | Continues on CPU |
| Venv | Create `.venv` if missing | Hard fail if no Python 3.10+ |
| Pip | fastapi, uvicorn, rapidocr, onnxruntime, huggingface_hub, … | Hard fail on core; soft-skip optional torch/kokoro |
| ONNX Runtime | Reuse if present; else GPU wheel or CPU fallback | Hard fail if neither works |
| UI | Require `frontend\dist\index.html` | Hard fail — tells you to run `build_release.ps1` |
| Ollama | Start `ollama serve` if needed; winget install if missing | Hard fail with download link |
| Phi | `ollama pull phi3.5:3.8b` if not listed | Hard fail |
| Local env | Write `config\env\local.yaml` | — |
| Weights | HF snapshot Vaani + Systran large-v3; Piper ONNX+JSON | Hard fail if download incomplete |
| Warm | RapidOCR dummy image; Ollama short chat | OCR warm hard; Ollama warm soft |
| Verify | Packages, dist, local.yaml, weights, Ollama tags | Hard fail if any missing |
| State | `runtime\setup_state.json` | — |
| Start | uvicorn + Chrome app window | Blocks until server exits |

### CLI (developers / IT)

```powershell
cd C:\Projects\Swasthya-Sathi
.\.venv\Scripts\python.exe deploy\appliance_setup.py              # console setup
.\.venv\Scripts\python.exe deploy\appliance_setup.py --gui        # progress window + start
.\.venv\Scripts\python.exe deploy\appliance_setup.py --start      # setup then start
.\.venv\Scripts\python.exe deploy\appliance_setup.py --start-only # skip setup
.\.venv\Scripts\python.exe deploy\appliance_setup.py --force      # redo even if state ok
.\.venv\Scripts\python.exe deploy\appliance_setup.py --verify-only
```

Frozen `Setup.exe` with no args ≡ `--gui --start`.

## 7. Device profile (`local.yaml`)

Setup writes `config\env\local.yaml`, for example:

```yaml
name: local
device: cuda          # or cpu
vram_ceiling_mb: 7488 # VRAM - ~700 MB headroom when GPU present
max_resident_gpu_models: 1
default_precision: fp16  # fp32 on CPU
internet_allowed: true
arch: x86
encrypt_at_rest: false
data_dir: ./_session_data
```

Kiosk start sets `SS_ENV=local`. If `local.yaml` is missing, the app falls back to `dev_4060`.

Supported env names in code: `local` | `dev_4060` | `cloud` | `orin`.

## 8. Runtime after start

| Item | Value |
|------|--------|
| URL | `http://127.0.0.1:8000` (UI + `/api`) |
| Health | `GET /api/health` |
| Ready | `GET /api/ready` (`ready`, `warming`, `unavailable`) |
| Browser | Chrome `--app=` when found; else default browser |
| Stop | Close the server console / stop the process |

Warmup is best-effort: missing STT/TTS appear under `unavailable`; OCR+LLM can still run.

## 10. Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| `npm` not recognized in `build_release.ps1` | PATH not refreshed after Node install | Script now uses full `npm.cmd` path; open a new shell or re-run fixed script |
| Setup says app screens missing | No `frontend\dist` | Run `build_release.ps1` on build PC; re-copy folder |
| Setup can't find Python | No 3.10+ on PATH | Install from python.org; re-run Setup |
| Ollama errors | Not installed / not running | Install from ollama.com; open Ollama once; re-run Setup |
| Vaani / Whisper download fails | Network / HF rate limit | Retry Setup; optional `HF_TOKEN` for higher limits |
| PyInstaller “running as admin” warning | Elevated PowerShell | Use normal user PowerShell; build still works |
| `Setup.exe` path errors | Exe moved alone | Keep exe beside `deploy\` and the rest of the tree |
| STT unavailable in `/api/ready` | Weights incomplete | Re-run Setup (`--force`) until `model.bin` exists under Vaani path |
| Port 8000 in use | Old server still running | End old python/uvicorn process; start again |

### Verify from a developer shell

```powershell
cd C:\Projects\Swasthya-Sathi
.\.venv\Scripts\python.exe deploy\appliance_setup.py --verify-only
```

Expect `READY`. Any printed problems must be fixed before clinics rely on the box.

## 11. Security & distribution notes

- `SwasthyaSathiSetup.exe` is **unsigned** unless you code-sign it; SmartScreen shows *"Windows protected your PC"* on first run → **More info → Run anyway**. To remove the warning, sign with an Authenticode (OV/EV) cert via `signtool` after the ISCC step, or add `SignTool` to `installer.iss`.  
- The installer is **per-user** (`PrivilegesRequired=lowest`) and installs to `%LOCALAPPDATA%\Programs\SwasthyaSathi` so first-run can write `.venv`, `models\weights`, `runtime`, and logs without admin.  
- First run downloads third-party weights (Hugging Face, Ollama). Review licenses for commercial distribution (Vaani/ARTPARK Apache-2.0; Phi MIT; RapidOCR Apache-2.0).  
- Do not commit large `models\weights\*.bin`, `.venv\`, or `Setup.exe` to git if policy forbids binaries — ship them in the release zip instead.  
- Session data lives under `_session_data\` and is reaped by TTL (see `DEPLOY.md`).
